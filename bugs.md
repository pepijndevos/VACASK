# VACASK C++ source audit - bugs

Audit of `.cpp` and `.h` files in [include/](include/), [lib/](lib/), [simulator/](simulator/), [demo/](demo/). Each item is a real or strongly-suspected defect; severity varies. Style-only nitpicks omitted.

## Critical (logic inversion / incorrect control flow)

- [x] **1.** **[lib/coretran.cpp:374](lib/coretran.cpp#L374)** — Inverted error check in `TranCore::populateStructures()`. The second `createJacobianEntry` call returned `false` when `ok` was `true` (which means: succeed → bail out; fail → proceed). Fixed by changing `ok` to `!ok`, matching the sibling check at [line 370](lib/coretran.cpp#L370).

- [x] **2.** **[lib/coretran.cpp:673-677](lib/coretran.cpp#L673-L677)** — `setError(TranError::NoiseMode)` was invoked when `params.noisemode` was invalid but the coroutine did **not** `co_yield CoreState::Aborted`; execution continued with a bad noise mode. Fixed by adding the missing `co_yield CoreState::Aborted;` right after `setError`, matching the sibling Fmax/Oversample/Fmin/Rows branches.

- [x] **3.** **[lib/coretran.cpp:1249-1270](lib/coretran.cpp#L1249-L1270)** — Originally the trapezoidal LTE filter computed `correct` from a live slope/crossing test and then silently overrode it with `correct = true;`, leaving the `kdelta`/`hcross` math as dead-but-compiled code. Rechecked: the crossing-detection block is now explicitly commented out with an explanation ("Disabled for now"), and `correct = true;` is documented as deliberate ("kept so that we can later enable the above code for crossing detection"). The always-correct behavior + retained `if/else` is now intentional, documented scaffolding rather than a silent override. No longer a defect.

- [x] **4.** **[lib/coretran.cpp:364](lib/coretran.cpp#L364)** — `if (!node1 | !node2)` used bitwise `|` instead of logical `||`. Both operands are pointer-style booleans, so the value was correct, but short-circuit evaluation was lost and the line read as a typo. Codebase-wide scan ran four grep variants filtered against the bit-flag noise (`*Flags`, `*MASK`, `Component::*`, `static_cast`, address-of, etc.) — this was the **only** instance of `&`/`|` standing in for `&&`/`||`. Fixed to `||`.

- [x] **5.** **[lib/circuit.cpp:376-380](lib/circuit.cpp#L376-L380)** — Silent shadowing of an outer name. The `while` condition's `pos` is *not* the inner `pos` (which is out of scope past the closing brace) — it binds to the *outer* `pos` introduced by the structured binding `auto [fs, pos, line, offset] = itld.location().data();` at [line 294](lib/circuit.cpp#L294). The outer `pos` is a `FileStackFileIndex` describing the source location of the `load` directive and is constant for the whole `do/while`, so the loop's exit no longer depends on whether a `*` remains in `asName`. Two failure modes: when outer `pos != std::string::npos` (the common case for load directives sourced from a real file), the loop is infinite once the inner `find("*")` returns `npos`; when outer `pos == std::string::npos`, the loop runs exactly once. Path only reached when a user passes a `map = ["...", "...*..."]` argument on a `load`, so the test suite hadn't exercised it. Fix: hoist the find result into its own name (`starPos`) and use it in the condition. *Fixed.*

- [x] **6.** **[lib/circuit.cpp:1274](lib/circuit.cpp#L1274)** — `unknownCountExcludingGround = atUnknown-1;` — `atUnknown` is an unsigned `UnknownIndex` (`uint32_t`); `atUnknown==0` wrapped to ~4.29e9. Fixed with `atUnknown>0 ? atUnknown-1 : 0` — the degenerate "no unknowns at all" case correctly yields a count of 0 instead of wrapping.

- [x] **7.** **[lib/outrawfile.cpp:106](lib/outrawfile.cpp#L106)** — `outStream.seekp(outStream.end);` bound to the one-argument `seekp(pos_type)` overload, seeking to absolute byte 2 (the value of the `end` seekdir enumerator) rather than to end-of-stream. The bug was the call arity, not the `end` spelling. Fixed to the two-argument form `outStream.seekp(0, std::ios_base::end);`. After rewriting the point count in `epilogue()`, the put pointer is now correctly returned to end-of-file before close.

- [x] **8.** **[lib/filestack.cpp:170-178](lib/filestack.cpp#L170-L178), [224-229](lib/filestack.cpp#L224-L229)** — Off-by-one in `addRpnString`: `return -(rpnStringStack.size()+1)` returned `-2` for the first string, but `cString` decodes negative ids as `rpnStringStack[-id-1]`, so `-2` → `rpnStringStack[1]` (OOB; only `[0]` exists). Encoding intent confirmed with author: file ids start at 0 (first file = toplevel netlist), string ids start at -1. Fixed to `return -static_cast<FileStackFileIndex>(rpnStringStack.size());` so the first string → -1 → `rpnStringStack[0]`. **Note: dormant code** — `addRpnString` has no callers and `rpnStringStack` is never populated/read on any live path; the whole negative-id / RPN-string subsystem is unwired scaffolding (kept intentionally per repo policy). Fix is correctness-for-future-use only, zero runtime impact today.

- [x] **9.** **[lib/parser.cpp](lib/parser.cpp), [include/parser.h](include/parser.h)** — Each of `parseNetlistString` / `parseExpression` / `parseParameters` had a `const std::string&` overload plus a `const std::string&&` overload. The rvalue overloads' `stream.str(std::move(input))` was a fake move (`std::move` on a `const` rvalue copies), so they were no faster than the lvalue versions despite the comment; the duplicated bodies had also drifted (`parseNetlistString(const std::string&&)` was missing the `acctNew.parse++` its lvalue twin had). Note: because callers pass string *literals*, the rvalue overloads were the ones actually selected. Fixed (Option C) by collapsing each pair into a single **by-value** overload `parseX(std::string input, ...)`: `addStringFile(input)` makes the unavoidable file-stack copy, then `stream.str(std::move(input))` genuinely moves into the parse stream. Same copy count as a correct move overload, half the functions, no duplication, single home for the `parse` counter. `addStringFile` always copies into `stringsPool`, so no further move is possible there.

- [x] **10.** **[simulator/main.cpp:29](simulator/main.cpp#L29) vs [109](simulator/main.cpp#L109)** — Help text advertised `--extratomlfile` (no hyphen) but the parser only accepted `--extra-tomlfile`, so the documented switch was untriggerable. Fixed in working tree: help text now reads `--extra-tomlfile`, matching the parser.

- [x] **13.** **[lib/klumatrix.cpp](lib/klumatrix.cpp)** — Loop filled `AP[col]` only on a transition into a new non-empty column, then set `AP[atCol+1]=nnz` at the end, leaving leading/interior/trailing empty columns' `AP[]` entries unwritten (garbage with raw `new[]`). Fixed on `main` by rewriting the column-pointer construction to the standard CSC "close-out" form: `AP[0]=0`, then for each entry close every column up to `col` at the running nonzero count (`while (curCol < col) AP[curCol+1]=atNz`), and after the loop close all remaining columns up to `AN` (`while (curCol < AN) AP[curCol+1]=atNz`). Now correct for empty/gapped/trailing columns independent of the diagonal-entry invariant; identical `AP` to before for fully-populated matrices. (On `hbac` the garbage-read was already mitigated by the switch to resizable containers; this gives `main` a correct builder.)

- [x] **14.** **[lib/klumatrix.cpp](lib/klumatrix.cpp)** — `dumpSparsity`, `dump`, and `dumpVector` took an `std::ostream& os` but wrote to `std::cout` in several places. `dumpSparsity` ignored `os` entirely (newlines and `x`/`.` went to stdout). `dump`/`dumpVector` did the `copyfmt` save/restore against `std::cout` instead of `os` — so they snapshot/restore the wrong stream's flags and left `os` permanently in scientific/precision mode — plus one stray `std::cout << "\n"`. Fixed on `main`: all output and the `copyfmt` save/restore now use `os` (snapshot `oldState.copyfmt(os)` at entry, restore `os.copyfmt(oldState)` at exit). Verified no `std::cout` remains in the file.

- [x] **15.** **[lib/pool.cpp:102](lib/pool.cpp#L102)** — `CStringPool::dump(std::ostream& os, ...)` printed the string count to `std::cout` instead of `os`. Fixed: now writes to `os`, consistent with the rest of the function.

- [x] **16.** **[lib/pool.cpp:42-49](lib/pool.cpp#L42-L49)** — ~~`allocate()` silently returns `nullptr` if the new block can't satisfy the request.~~ **Original claim invalid on recheck.** `newSize` is set to `need*growthFactor` whenever `lastBlock->size*growthFactor < need`, so the new block always has `size >= need`; a fresh `Block` has `used==0`, and `Block::allocate(need)` succeeds whenever `used+need <= size`, which always holds. The size-mismatch path cannot occur. The *only* real nullptr path was the unchecked `malloc` in the `Block` ctor (true OOM). Fixed: `Block(size_t)` now throws `std::bad_alloc` if `malloc` fails ([include/pool.h](include/pool.h)), consistent with the `new`/throw style elsewhere. (Scan-loop semantics preserved — `Block::allocate()` still returns `nullptr` for "block full"; only the ctor throws.)

- [x] **17.** **[lib/outrawfile.cpp:32-36](lib/outrawfile.cpp#L32-L36)** — `std::asctime(std::localtime(&t))` used two shared static buffers (not thread-safe). Replaced with C++20 `<chrono>` + `std::format`: `floor<seconds>(system_clock::now())` truncated to whole seconds, then `zoned_time{current_zone(), now}` formatted via `std::format("{:%a %b %e %H:%M:%S %Y}", ...)`. Thread-safe, preserves local time and the original asctime-style layout (`Wed May 20 09:29:11 2026`). `<ctime>` include swapped for `<chrono>`/`<format>`. Verified the format string + tz lookup compile, link, and run on GCC 14.2.

## Memory and pointer safety

- [x] **18.** **[lib/sourceloc.cpp:46-62](lib/sourceloc.cpp#L46-L62)** — `Loc::toString()` dereferenced `fileStack` (from `FileStack::lookup(...)` via `data()`) without a null check. `operator bool` only guarantees `fileStackId_ != badFileStackId`, not that the FileStack still exists — `~FileStack` erases its `idToFs` entry, so a `Loc` outliving its FileStack yields `lookup()==nullptr` and a crash at the line-extraction. Fixed: a single guard right after `data()` returns `"<unknown location>"` when `fileStack` is null, covering every later `fileStack->...` use.

- [x] **19.** **[lib/sourceloc.cpp:104-110](lib/sourceloc.cpp#L104-L110)** — For string-input locations `toString()` did `return std::string("<string input>")`, discarding the source-line + caret context already built in `s`. Fixed: now appends the position (`line:column (0xoffset)`) and `in <string input>` to `s` and returns `s.str()`, preserving the visual context and mirroring the real-file format (substituting `<string input>` for the filename, skipping the inclusion chain).

- [x] **20.** **[lib/comdata.cpp:122-135](lib/comdata.cpp#L122-L135)** — `enumerateNatures()` set `n = unknown_natureId.size()` then `resize(n+1)` and looped `i<n`, leaving the last index (`n`) default-initialized. Fixed to follow the codebase convention where `n` is the unknown count *excluding ground*: `n = unknown_natureId.size()-1`, keep `resize(n+1)`, loop `i<=n` so index 0 (ground/reference) through `n` are all filled. Matches `resetTolerances`/circuit-dump indexing.

- [x] **21.** **[lib/an.cpp:350-388](lib/an.cpp#L350-L388)** — The swept-analysis `switch (state)` had `bool exitLoop;` uninitialized and only `case Finished` set it + `break`ed; `Aborted`/`Stopped`/`default` `co_yield`ed with no `break`. Because `co_yield` *suspends and can resume*, resuming after `Stopped` continued at the line after the yield and **fell through into `default`**, producing a bogus "Yielded value not supported" abort instead of resuming the core. Fixed: `exitLoop = false;` initializer + `break;` after every case, so resume-after-stop re-enters `while (cc)` and resumes the core. Applied the same missing-`break` fix to the sibling no-sweep loop at [an.cpp:503-525](lib/an.cpp#L503-L525) (no `exitLoop` there — `Finished` is terminal so a plain `break` lets the next `while(cc)` complete the core, while `Stopped` correctly continues).

- [x] **22.** **[lib/an.cpp:550-558](lib/an.cpp#L550-L558)** — `resume()` silently returned `AnalysisState::Aborted` when the coroutine was invalid/done *without* updating `lastCoroutineState`, so the return value and the member could diverge and mislead `finish()`'s cleanup branch. Resolved by making it a hard error: resuming an invalid or already-finished coroutine is a usage error (and resuming a finished coroutine is UB), so `resume()` now `throw`s `std::runtime_error` in that case instead of returning a stale state. Added `#include <stdexcept>`. The normal `run()` path is unaffected (it guards with `done()` + `InternalError` before each `resume()`).

- [x] **23.** **[simulator/cmd.cpp:549](simulator/cmd.cpp#L549)** — `evaluateArgs(...)`'s return value was ignored, so a failed argument expression evaluation was silently swallowed and `cmd_elaborate` proceeded with partial `args`. Fixed: now `if (!evaluateArgs(...)) return false;`, propagating the error in `s` like the sibling `evaluateExpressions` check just above.

- [x] **24.** **[lib/value.cpp:94-113](lib/value.cpp#L94-L113)** — **By design, not a bug.** `Value::convert()`'s post-`~Value()` switch deliberately handles only the heap-allocating types (`String/IntVec/RealVec/StringVec/ValueVec`). `Int`/`Real` are stored inline in the union and need no allocation; `dest.type_ = to;` after the switch sets the tag for all targets, and `convertValue<...>` writes the scalar directly. Confirmed intentional.

- [x] **25.** **[lib/status.cpp:51-59](lib/status.cpp#L51-L59)** — `Status::prefix(const std::string& msg)` wiped `message_` to `""` when `msg.size()==0` (the `else` branch did `message_ = msg`). Fixed: empty `msg` is now a no-op (`if (!ignoreFlag && msg.size()>0)`), and the separator logic mirrors `set()` — only insert `"\n"` when `message_` is non-empty, so prefixing onto an empty message no longer leaves a trailing newline.

- [x] **31.** **[lib/devvisrc.cpp:114](lib/devvisrc.cpp#L114) (+ 5 similar in [lib/devctlsrc.cpp](lib/devctlsrc.cpp))** — `static ParameterIndex principalXxx = std::get<0>(Introspection<...>::index("..."));` paired with `principalParameterIndex()` methods that returned `std::make_tuple(principalXxx, true)`. ## Parser ([lib/dflparser.y](lib/dflparser.y))
