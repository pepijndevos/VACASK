# Bug audit — feature/errorstack branch

Audited: `git diff 1e01cd58c14dead0f0e6ba32776a6b2dab6b4240..HEAD` (branch feature/errorstack vs main),
104 files / ~3.9k changed lines, migrating error reporting from `Status&`/return-codes to an
`ErrorConsumer`/exception-based error-stack.

## Bugs introduced by this branch

- [x] 1. **AC / Noise / HBAC / ACSP / ACSTB / ACXF analyses lose node-name resolution in matrix-error messages** — `lib/coreac.cpp`, `lib/corenoise.cpp`, `lib/corehbac.cpp`, `lib/coreacsp.cpp`, `lib/coreacstb.cpp`, `lib/coreacxf.cpp`
  `setResolver()` is only wired up for `OperatingPointCore::jac` (`lib/coreop.cpp:40`) and `HBCore::bsjac` (`lib/corehb.cpp:550`). None of the six AC-family cores' `acMatrix` (or, for HBAC, `jacSpec`) ever got a resolver registered — `HBACUnknownNameResolver` (`corehbac.cpp:46`) was dead code, and `coreacxf.cpp:393` still built a local `UnknownNameResolver` that was never actually used (leftover from the pre-refactor code, which passed it to the now-removed `formatError()`). Before the refactor, each site built a resolver at the point of formatting the error and passed it explicitly. Originally the audit only caught this in `coreac.cpp`/`corenoise.cpp`/`corehbac.cpp`; `coreacsp.cpp`/`coreacstb.cpp`/`coreacxf.cpp` (AC sensitivity/stability/transfer-function analyses) had the identical gap and were missed in the first pass.
  Failure scenario: run `ac`/`noise`/`hbac`/`acsp`/`acstb`/`acxf` on a circuit whose small-signal matrix goes singular or produces NaN/Inf — the error now reports a raw row/column index instead of the node name.
  **Fixed**: added an owned `UnknownNameResolver resolver_` member to `ACCore`/`NoiseCore`/`ACSPCore`/`ACStbCore`/`ACXFCore`, wired via `acMatrix.setResolver(&resolver_)` in each constructor (mirroring `OperatingPointCore`); removed the dead, never-used `auto nr = UnknownNameResolver(circuit);` in `coreacxf.cpp`. For HBAC, moved `HBACUnknownNameResolver` from a local class in `corehbac.cpp` into `corehbac.h` (mirroring `HbUnknownNameResolver`/`corehb.h`), gave it a deferred `setFreqCount()` (frequency count isn't known until `rebuild()` computes `nf = stencil.nRows()`), added an owned `hbacResolver_` member, and wired `acMatrix.setResolver(&hbacResolver_)` at that point in `HBACCore::rebuild()` — `jacSpec` intentionally left unwired (per author: it only stores spectra, never factored/solved, so it never produces row/col-indexed errors). Verified with two full real `cmake --build` runs (Debug, parallel) — clean compile and link of `simlib`, `vacask`, and all test/demo binaries both times.

- [x] 2. **HB analyses lose detailed non-convergence diagnostics** — `lib/corehbnr.cpp` / `include/corehbnr.h`
  `NRSolver::run()` now reports non-convergence via virtual hook `pushConvergenceReport()` (default no-op). `OpNRSolver` overrides it correctly (`coreopnr.cpp:1151`); `HBNRSolver` still only implements the old `formatConvergence()` (`corehbnr.cpp:784`, worst delta/node/frequency) but was never given a `pushConvergenceReport()` override, so it silently falls back to the no-op base. `formatConvergence()` is now dead code.
  Failure scenario: an `hb`/`hbac` run fails to converge — user sees only "NR solver failed to converge." with no worst-delta/node/frequency breakdown.
  **Fixed**, mirroring the `OpNRSolver` pattern exactly: extracted the string-building logic into a shared free function `formatHbConvergence(...)` (`include/corehbnr.h`/`lib/corehbnr.cpp`), added a data-carrying `HbNrConvergenceReport` error class whose `format()` calls that free function, rewired `HBNRSolver::formatConvergence()` to call the free function too (eliminating the duplicated logic), and added the missing `HBNRSolver::pushConvergenceReport(ErrorConsumer&)` override that pushes an `HbNrConvergenceReport` snapshot (preventedConvergence, iterationConverged, iteration, maxDelta, deltaWithinTol, maxDeltaNode, maxDeltaFreqIndex, maxDeltaFreq). Verified with a full compile of all 117 project source files — zero errors.

- [x] 3. **(Latent) Convergence report narrowed to only fire when `itlim` is exhausted** — `lib/nrsolver.cpp:428-430`
  Old code emitted the convergence error whenever the loop exited with `!converged`; new code gated it behind `iteration >= itlim`. Currently dead (`OpNRSolver`/`TranNRSolver`/`HBNRSolver` hooks always return `true`), but a future subclass whose hook returns `false` before `itlim` is hit would have gotten zero explanation instead of even the generic message. **Fixed**: dropped the `iteration >= itlim &&` clause, relying solely on `errors.pushedCount() == errorMark` (already captured at the top of `run()`) to decide whether to emit the generic fallback report — restores the base commit's "no concrete failure recorded" semantics regardless of why the loop exited. Verified with a syntax-only compile of `lib/nrsolver.cpp`.

- [x] 4. **`KluMatrixCore::formatError()`/`errorRow()`/`errorRank()`/`errorElement()` are dead and lie** — `lib/klumatrix.cpp`, `include/klumatrix.h`
  All real error state moved to `ec.push(...)`; the old `lastError`/`errorIndex`/`errorRank_`/`errorNan` fields are only ever reset, never set. These public accessors now always report "no error" / 0 / false. No current callers, so inert today, but misleading if reused. **Fixed**: verified all 10 `Error` enum cases have equivalent `Klu*Error` classes pushed at their actual failure sites, then removed `formatError()`, the now-orphaned `errorElement()`/`errorRow()`/`errorRank()` accessors, the backing fields, all `clearError()` call sites, and the now fully-unreferenced `enum class Error` (plus its re-export in `klubsmatrix.h`). Verified with a full syntax-only compile of every `lib/*.cpp` and `simulator/*.cpp` file — zero errors.

- [x] 5. **Leftover debug statement** — `simulator/main.cpp:49`
  `auto a = error_registry();` copies the whole error registry into an unused local. Harmless, looks like an accidental commit. **Fixed** (uncommitted working-tree change removes the line and the now-unused `errorstack.h` include).

## Pre-existing bugs (present before this branch, found during the audit)

- [x] 7. **`Analysis::finish()` silently discards a "restore circuit state" failure via variable shadowing** — `lib/an.cpp:613-629`
  `bool ok = true;` at the top of `finish()` is shadowed by `auto [ok, hierarchyChanged, needsCoreRebuild] = circuit.elaborateChanges(...)` inside the `preSweepValuesStored` block. On failure, `ok = false` only sets the inner shadowed variable; `return ok;` at function end returns the untouched outer `ok`.
  Failure scenario: a swept analysis completes, then restoring pre-sweep parameter/option values fails (e.g. topology changed during the sweep) — failure text is appended to `s`, but `finish()` still returns `true`; a caller branching on the boolean return treats it as a clean finish while the circuit is left in the last-swept state. Confirmed verbatim in base commit; untouched by this branch. **Fixed** (uncommitted working-tree change renames the structured-binding variable to `okElaborate`, removing the shadowing so `ok` is correctly set on failure).

- [x] 8. **`DCXFCore::coroutine()` always yields `Finished`, even after a mid-sweep solve/finiteness failure** — `lib/coredcxf.cpp`
  The per-source loop sets `error = true; break;` on failed `jacobian.solve()` or non-finite solution, but `error` is only used for a debug print — the final `co_yield CoreState::Finished;` was unconditional. Sibling coroutines (`ACCore`, `NoiseCore`, `HBACCore`, `DCIncrementalCore`) all gate the terminal yield correctly; `DCXFCore` was the outlier.
  Failure scenario: `dcxf` with 2+ sources where the solve/finiteness check fails on the first — loop breaks, later `tf[]`/`zin[]`/`yin[]` entries stay stale/zero, but the core reports success; a raw-file point is written with truncated/wrong data and the pushed error is never surfaced. Confirmed byte-identical in base commit. **Fixed** (uncommitted working-tree change wraps the final yield in `if (error) { co_yield Aborted; } else { co_yield Finished; }`).

- [x] 9. **`TranNRSolver::advanceNoise()` swallowed a `collectNoiseScaling()` failure** — `lib/coretrannr.cpp` (base commit ~line 155)
  Failure path built `std::make_tuple(false, changed)` but never `return`ed it, falling through to unconditional success. **Already fixed on this branch** (HEAD `coretrannr.cpp:154` has the `return`) — incidental, not a deliberate targeted fix.

- [x] 10. **Dead error-handling block in `resolveSave()`** — `lib/anacsp.cpp`, `lib/anacstb.cpp` (base commit)
  An unconditional `if (verify) return st; else return true;` made a trailing block (the only call to `smsigCore.formatError(s)`) unreachable — any error state in `smsigCore` was never surfaced. Inert, not data-corrupting. **Already removed on this branch** — incidental cleanup.

## Bugs introduced by this session's own fix for item 2

- [x] 11. **Segfault in `HBNRSolver::formatConvergence()` on the very first NR iteration** — `lib/corehbnr.cpp`
  The item-2 fix extracted the delta-report string-building into a free function `formatHbConvergence(...)` and passed `spurs_.spectrum()[maxDeltaFreqIndex]` as a plain function argument. C++ evaluates all arguments before the call, so that indexing happened unconditionally — including on NR iteration 1, where `checkDelta()` (the only place that ever sets `maxDeltaFreqIndex`) has not run yet, leaving it at an indeterminate/garbage value. The original code had this indexing safely nested inside `if (iteration>1) {...}`; moving it into an eagerly-evaluated call argument silently dropped that guard.
  Reproduced with `test/test_hb3.sim`: `vacask -dp test_hb3.sim` segfaulted every time. `gdb` backtrace: `HBNRSolver::formatConvergence()` (`corehbnr.cpp:822`) → `NRSolver::postConvergenceCheck` (`nrsolver.cpp:77`, a debug-print call site) → `HBNRSolver::postConvergenceCheck` → `NRSolver::run()` → `HBCore::runSolver`/`coroutine()`.
  **Fixed** (per user's design, not just a bounds-check patch): introduced an explicit `deltaCheckValid` member on `HBNRSolver`, `false` in the constructor and reset `false` at the top of `initialize()` ("beginning of the NR loop"), set `true` inside `checkDelta()` right after its reset block populates well-defined values. `formatHbConvergence()`/`HbNrConvergenceReport` now gate the whole delta section (including the `spurs_.spectrum()[...]` lookup, computed conditionally by the caller instead of eagerly) on `deltaCheckValid` instead of `iteration>1`, with an `else` branch reporting "no convergence data available". The same validity-flag pattern was then applied to `OpNRSolver` for symmetry/robustness (`residualCheckValid`/`deltaCheckValid`, replacing the `settings.residualCheck`/`iteration>1` gates in `formatOpConvergence()`/`OpNrConvergenceReport`, with a combined "no convergence data available" fallback when neither is valid) — not itself crash-prone (its worst-node fields are nullable `Node*`, so no OOB access), but the same "gate on an incidental proxy instead of an actual validity flag" fragility. Additionally hardened both node-name resolutions to `(maxDeltaNode/maxResidualNode && deltaCheckValid/residualCheckValid) ? ...->name() : Id()`, so a solver instance reused across multiple `run()` calls (continuation mode, successive sweep points) can't leak a stale prior-run node identity into the pushed error struct even though it isn't currently rendered.
  Verified: `test_hb3.sim` runs to completion without crashing.
